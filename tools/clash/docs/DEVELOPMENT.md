# clash Development Guide

> AI uses this guide to upgrade this module.

## upstream

- Homepage: <https://github.com/MetaCubeX/mihomo>
- Docs: <https://wiki.metacubex.one/>
- Releases: <https://github.com/MetaCubeX/mihomo/releases>

## Installation

- aibox module: `aibox install clash` (automatically downloads the platform-appropriate mihomo binary from the GitHub release)
- upstream: download `mihomo-{os}-{arch}-v{ver}.gz` + `gunzip`

## Testing

- Self-check: `aibox clash doctor`
- Status: `aibox clash status` (mihomo status + current node + latency)
- Probe: `aibox clash test [url]`

## Module Configuration

- Ports: 7890/tcp:mixed (socks5+http mixed port) + 9090/tcp:api (external-controller)
- Credentials: state `CLASH_SECRET` (API auth, randomly generated by `gen_secret`)
- Deployment target: app root `$AIBOX_HOME/apps/clash` (config.yaml/providers/pool.yaml/state/logs, all permission 600)
- Autostart: nohup+pid (simple cross-platform resident process, not an init system; if mihomo dies aibox detects and falls back to a static proxy)
- Dependencies: none external (mihomo is delivered by aibox; gunzip is bundled with the system)
- Customization points: does not parse subscription yaml itself (mihomo `proxy-providers` consumes the subscription URL); `url-test`/`fallback` groups auto-test speed/switch; aibox refreshes the subscription as a fallback every `>1 week`

## Upgrade Procedure

1. Check upstream latest version: mihomo GitHub releases latest (`latest_mihomo_tag` calls the GitHub API)
2. `aibox update clash` (upgrades the mihomo binary + refreshes the subscription)
3. Verify: `aibox clash status` + `aibox clash test`
